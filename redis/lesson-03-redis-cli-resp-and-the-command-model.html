03Concept · Phase 0 · Redis

Talking to Redis: redis-cli, RESP & the Command Model

Lessons 01 and 02 put a flat dictionary of typed containers inside a single-threaded event loop. Before Phase 1 opens those containers one by one, you need the contract on the socket between your app and that loop: how redis-cli drives the server, how RESP frames binary-safe commands and replies on TCP, how Redis parses arity and key locations, and how to read the Time Complexity line off any command page without misjudging N.

Original study chapter. Written from scratch for backend and system-design interviews — and for everyday debugging on port 6379. Target behavior follows Redis Open Source 8.10 (latest stable GA patch 8.10.3; 8.12 in release candidate as of late 2026). The Build section uses zero third-party libraries — pure Python 3 standard-library socket to send and decode raw RESP2 and RESP3 frames — paired with redis-cli. 00 Failure first

The invisible wire: why raw text breaks and OK hides the frame ▸

Most engineers meet Redis through a client SDK or the 127.0.0.1:6379> prompt, so the wire disappears behind neat strings and helper methods. The moment you drop into a shell script, a raw TCP socket, or a production ACL review, four surprises surface at once:

  • Naive text framing mangles binary payloads — typing SET note hello\r\n over nc works because inline commands split on spaces and stop at \r\n. Pass a JSON value with spaces, a newline, or a null byte (\x00) that way and the parser splits the payload into bogus arguments or rejects it with ERR syntax error.
  • redis-cli changes its output format behind your back — in a terminal it prints human sugar like (integer) 2, 1) "apples", and (nil), while stdout redirected to a pipe silently flips to raw mode and drops the type tags. Scripts written by eyeballing interactive output break in cron jobs.
  • Null vs. empty string vs. RESP2 collections — SET k "" returns "" (0 bytes) on read, whereas a missing key returns (nil); under RESP2 both missing bulk strings ($-1) and missing arrays (*-1) mean null, while HGETALL arrives as a flat list instead of a map and SUBSCRIBE locks the connection out of normal commands.
  • Complexity misreading — treating every O(N) command alike misses what N counts: KEYS scans the entire database, HGETALL scans one hash, and MGET loops over your caller-supplied keys.

Every one of those surprises vanishes once you separate what the CLI displays from the RESP frame on the socket and the command metadata inside the server. Watch a round trip cross port 6379 first.

The CLI is a translator, not the protocol

When redis-cli prints (integer) 2, (nil), or 1) "apples", those labels never cross the network. The server emits a single prefix byte — :, $-1 (or _ in RESP3), * — and the client decides how to display or return it.

01 Driving the server

redis-cli: REPL, shell scripts, and safe probes

Every Redis installation ships with redis-cli, and engineers reach for it in three distinct roles: an interactive REPL during development, a composable Unix command in shell scripts, and a zero-dependency diagnostic tool during incidents. Mixing up those modes — especially TTY formatting and credentials — causes subtle bugs.

  • Interactive REPL & connection basics — running redis-cli with no command opens a prompt with Tab completion, command history, inline syntax hints, and built-in HELP <command> or HELP @<group>. Connect via host/port (-h, -p), TLS (--tls), or a URI (-u redis://user:pass@host:6379/0, or rediss:// for TLS). Never pass secrets with -a in shared shells because process listings (ps) and shell history expose it; export REDISCLI_AUTH or pass --askpass instead. Use -c against Redis Cluster so redis-cli follows -MOVED and -ASK redirects automatically (and remember Cluster uses DB 0 only; -n <db> applies to standalone servers). Prefixing any REPL line with an integer (5 PING) repeats that command cleanly.
  • Shell scripting & binary inputs — redis-cli detects whether stdout is a terminal. On a TTY it pretty-prints quotes and type tags; when piped (redis-cli GET k | jq) it automatically switches to raw output. Pass --raw to force raw strings on a TTY, or --no-raw to preserve type annotations inside pipes. Use -x to read the final argument from stdin without shell-escaping gymnastics (redis-cli -x SET doc < body.json), -X <tag> to substitute a placeholder token from stdin, --quoted-input for C-style escapes like "\x00", and -e so a Redis error exits non-zero in CI/CD scripts. Use --json (defaults to RESP3; pass -2 if RESP2 is required) or --csv for machine-readable exports.
  • Safe production probes & bulk loading — --scan --pattern 'sess:*' --count 500 replaces dangerous KEYS calls with cursor-paced scans (L02). --bigkeys counts the largest element-count keys by type, --memkeys samples actual byte footprints, and --hotkeys samples the hottest keys (requires an *lfu eviction policy; throttle all three with -i 0.1 to pause 100 ms every 100 scan iterations). --stat streams a rolling one-line-per-second snapshot of keys, memory, clients, and ops/sec; --latency continuously measures round-trip min/avg/max; and --pipe streams raw RESP frames straight into TCP without waiting per reply (L22).

02 Wire protocol

RESP2 & RESP3: byte-prefixed framing and HELLO 3 ▸

Why didn’t Redis adopt HTTP+JSON or a compact binary schema like Protobuf? Because RESP (REdis Serialization Protocol) targets a narrow sweet spot between them: fast to parse (read one prefix byte and an ASCII length, then memcpy), human-readable in packet captures, and binary-safe up to 512 MB per bulk string with zero JSON escaping or schema compilation.

Every frame starts with a single ASCII type byte and ends every line with \r\n (CRLF). Client requests always travel as a RESP Array of Bulk Strings — for instance, GET cart:42 is *2\r\n$3\r\nGET\r\n$7\r\ncart:42\r\n. Redis also accepts plain space-separated inline commands (PING\r\n) for quick manual debugging over telnet or nc, but real drivers never rely on inline syntax because it cannot protect whitespace, newlines, or binary bytes inside an argument.

RESP2 served Redis for over a decade with five types (+, -, :, $, *). That minimalism forced awkward client workarounds: HGETALL arrived as a flat array you had to zip into pairs, SMEMBERS looked identical to a list, booleans became 1/0, missing keys used $-1 while missing multi-bulks used *-1, and SUBSCRIBE flipped the whole socket into a restricted pub/sub mode where regular commands stopped working. Starting in Redis 6.0, RESP3 added rich semantic types and out-of-band push frames — opt-in via HELLO 3 so every TCP connection still starts in RESP2 for backward compatibility.

Why framing invites pipelining (preview of L22)

Because every RESP request and reply declares its exact element count (*N) and byte lengths ($len), nothing forces a client to wait for reply #1 before transmitting request #2. A client can write 500 commands into one TCP send buffer and parse the 500 framed replies cleanly as they stream back — the exact mechanism behind redis-cli --pipe and client pipelines (L22) as well as RESP3 server-push tracking (L30).

03 Inside the server

The Command Model: dispatch, arity, key specs & subcommands

Once Redis parses a RESP Array into an argument vector — say ["ZADD", "lb", "100", "ada"] — the server does not jump straight to the dataset. Every command runs through a deterministic metadata table that checks four questions before touching memory:

  • 1 · Command & subcommand lookup — command names (and subcommands like OBJECT ENCODING or ACL CAT) are case-insensitive, while keys and values remain binary-exact. Unknown names fail immediately with ERR unknown command.
  • 2 · Arity check — every command stores an integer arity that counts the command name itself (and subcommand name for nested commands). A positive number means an exact count (GET k has arity 2; LRANGE k 0 9 has arity 4). A negative number means a minimum count: MGET has arity -2 (command + at least 1 key), and ZADD has arity -4 (command + key + score + member).
  • 3 · Flags, ACLs & mode gates — each command carries flags such as readonly, write, denyoom (reject writes if maxmemory is full while allowing DEL and GET), fast, and blocking, plus ACL categories like @read, @write, @string, @fast, or @slow. Read-only replicas reject write commands, MULTI queues valid commands while rejecting arity errors at queue time (L23), and ACL rules check both command permission and key pattern before execution.
  • 4 · Key specifications (Cluster & proxy routing) — legacy metadata used three integers (firstkey, lastkey, step), which worked for GET (1, 1, 1) and MSET (1, -1, 2) but broke when a key’s position depended on an argument like numkeys (ZINTERSTORE dst 2 k1 k2) or keyword tokens (SORT list STORE out). Starting in Redis 7.0 and standard across 8.x, COMMAND INFO exposes rich key specifications (begin_search, find_keys, access flags like RO/RW/UPDATE) so proxies, ACL key checks, and COMMAND GETKEYS locate every key without hardcoding grammars.
04 Reading complexity

Time complexity & @fast vs. @slow: what N really means

Lesson 02 warned that one slow command blocks the single-threaded event loop for every client. Every Redis command page opens with a Time complexity line — yet engineers repeatedly misread it because the letter N changes meaning from command to command. Never stop at the Big-O symbol; read the prose clause that defines N, M, and S.

Across Redis 8.10, complexity variables fall into five distinct meanings:

  • 1 · Whole database keyspace (N = keys in DB) — KEYS is O(N) across every key in the database, so its cost scales with total data even if only one key matches. RANDOMKEY is O(1).
  • 2 · Elements inside one key (N = collection length) — HGETALL, SMEMBERS, and LINDEX scale with the size of that single container. Fine on a 10-field profile hash; dangerous on an unbounded set of millions of user IDs. (Note: Redis 8.8’s ARGET reads sparse array indices in O(1) instead of LINDEX’s O(N) walk.)
  • 3 · Caller-supplied arguments (N = batch size you sent) — MGET is O(N) in the number of keys requested, and SADD/LPUSH are O(1) per item added (O(N) for N arguments). DEL has both: O(N) over the N keys named plus O(M) per non-string key holding M items (whereas UNLINK detaches in O(1) per key and frees large containers off-thread).
  • 4 · Position + returned slice (O(S+N) or O(log(N)+M)) — LRANGE k start stop costs O(S+N), where S is distance from the nearest list end (head for small lists, head or tail for large lists) and N is elements returned: LRANGE q 0 9 is effectively constant, while LRANGE q 0 -1 walks everything. ZRANGE costs O(log(N)+M), where N is sorted-set size and M is elements returned: reading top 10 from 10 million players is ~25 steps.
  • 5 · Multi-collection worst case (O(N*M)) — SINTER costs O(N*M) where N is the cardinality of the smallest set and M is the number of sets. Intersecting a 5-member set against a 5-million-member set does ~5 hash lookups, not 5 million.

Reading ACL speed tags accurately. Redis splits every command between two complementary ACL categories: @fast and @slow (inspectable via ACL CAT fast or COMMAND INFO). In Redis’s ACL definition, @fast covers O(1) commands (plus bounded O(log N) like ZADD and argument-looping commands like MGET, SADD, and LPUSH that never walk an arbitrary stored collection), while @slow covers everything else. That makes -@slow a handy ACL guardrail against accidental KEYS or HGETALL calls — with two crucial caveats:

What the interviewer probes next

1 · “Why does SET note "a\nb" break over raw nc/inline mode yet work fine from Python or redis-cli -x?” Inline parsing splits on ASCII spaces and ends the command at \r\n. Real clients and redis-cli -x send a RESP Array of length-prefixed Bulk Strings (*3\r\n$3\r\nSET\r\n...$3\r\na\nb\r\n), so Redis reads exact byte counts verbatim without scanning payload bytes for delimiters.

2 · “Why did Redis introduce RESP3 when RESP2 already worked?” RESP2 flattened maps and sets into generic arrays, overloaded nulls across $-1 and *-1, lacked native booleans and floats, and forced Pub/Sub onto a connection-locking state machine. Negotiating HELLO 3 adds native % Maps, ~ Sets, _ Null, # Booleans, , Doubles, | Attributes, and non-blocking > Push frames on the same socket.

3 · “If we strip -@slow from an app’s ACL user, can it still stall Redis?” Yes. Commands like MGET, SADD, and LPUSH carry @fast because they do not scan server-owned collections — they loop over caller arguments. A client sending 200,000 keys to MGET passes @fast and still blocks the single-threaded loop.

4 · “How does a Redis Cluster client route SORT or multi-key EVAL if keys can sit anywhere in the command?” Through COMMAND INFO’s key specifications (and COMMAND GETKEYS for server-side inspection), which describe begin_search and find_keys rules even when key counts depend on an argument like numkeys.

05 Build

Talk raw RESP2 & RESP3 over TCP and inspect command metadata

Client libraries normally hide the wire protocol. Writing thirty lines of pure Python socket code removes all mystery: you build the RESP request array yourself, send a newline and a null byte inside a value without escaping anything, compare GET and HGETALL before and after HELLO 3, and read arity plus @fast/@slow tags straight out of COMMAND INFO.

Verification checkpointRunnableRedis 8.10 · Python 3 stdlib
Raw RESP2/RESP3 frame encoder, decoder, and COMMAND INFO probe

Run against a throwaway local Redis 8.10 server on localhost:6379. Uses Python 3’s built-in socket module only (no packages to install) and cleans up every key via UNLINK.

Think it through

1 · Frame requests as Bulk String Arrays

Prefix the argument count with * and each argument with $<len>; binary payloads containing \n and \x00 pass straight through.

2 · Dispatch replies on byte 0

Scan to \r\n for scalars (+, -, :, _, #, ,, (), read exact byte counts for blobs ($, !, =), and recurse for aggregates (*, ~, %, >, |).

3 · Upgrade in place & inspect metadata

Send HELLO 3 to watch missing GET flip from $-1 to _, HGETALL flip from list to dict, and SMEMBERS flip to a set; then query COMMAND INFO and COMMAND GETKEYS.

The code

python 3 · stdlib only · resp_wire_probe.py

import socket
import uuid


class RedisReplyError(Exception):
    pass


def encode_cmd(*args):
    frames = [f"*{len(args)}\r\n".encode("ascii")]
    for arg in args:
        raw = arg if isinstance(arg, bytes) else str(arg).encode("utf-8")
        frames.append(f"${len(raw)}\r\n".encode("ascii") + raw + b"\r\n")
    return b"".join(frames)


def read_frame(f):
    line = f.readline()
    if not line.endswith(b"\r\n"):
        raise EOFError("Truncated RESP frame")
    prefix, body = line[:1], line[1:-2]

    if prefix == b"+": return body.decode("utf-8")
    if prefix == b"-": raise RedisReplyError(body.decode("utf-8"))
    if prefix == b":": return int(body)
    if prefix == b"_": return None
    if prefix == b"#": return body == b"t"
    if prefix in (b",",): return float(body)
    if prefix == b"(": return int(body)
    if prefix in (b"$", b"!", b"="):
        n = int(body)
        if n == -1: return None
        data = f.read(n)
        f.read(2)  # discard trailing \r\n
        if prefix == b"!": raise RedisReplyError(data.decode("utf-8", errors="replace"))
        return data[4:] if prefix == b"=" else data
    if prefix == b"*":
        n = int(body)
        return None if n == -1 else [read_frame(f) for _ in range(n)]
    if prefix == b"~":
        items = [read_frame(f) for _ in range(int(body))]
        try:
            return set(items)
        except TypeError:
            return items  # e.g. COMMAND INFO wraps key-spec Maps inside a Set
    if prefix == b"%":
        return {read_frame(f): read_frame(f) for _ in range(int(body))}
    if prefix == b">":
        return ("push", [read_frame(f) for _ in range(int(body))])
    if prefix == b"|":
        _attrs = {read_frame(f): read_frame(f) for _ in range(int(body))}
        return read_frame(f)
    raise ValueError(f"Unknown RESP prefix: {prefix!r}")


def send_cmd(sock, f, *args):
    wire = encode_cmd(*args)
    sock.sendall(wire)
    return wire, read_frame(f)


p = f"lab:resp:{uuid.uuid4().hex[:8]}"
k_bin, k_empty, k_miss, k_cart, k_tags = (
    f"{p}:bin", f"{p}:empty", f"{p}:miss", f"{p}:cart", f"{p}:tags"
)

with socket.create_connection(("127.0.0.1", 6379), timeout=5) as sock:
    f = sock.makefile("rb")
    try:
        payload = b"line1\nline2\x00end"
        wire, ok = send_cmd(sock, f, "SET", k_bin, payload)
        assert ok == "OK" and wire.startswith(b"*3\r\n$3\r\nSET\r\n")
        assert send_cmd(sock, f, "GET", k_bin)[1] == payload

        # RESP2: empty string vs null, flat array for HGETALL & SMEMBERS
        send_cmd(sock, f, "SET", k_empty, b"")
        assert send_cmd(sock, f, "GET", k_empty)[1] == b""
        assert send_cmd(sock, f, "GET", k_miss)[1] is None
        send_cmd(sock, f, "HSET", k_cart, "apples", "3", "note", "gift")
        send_cmd(sock, f, "SADD", k_tags, "cache", "ram")
        assert send_cmd(sock, f, "HGETALL", k_cart)[1] == [b"apples", b"3", b"note", b"gift"]
        assert isinstance(send_cmd(sock, f, "SMEMBERS", k_tags)[1], list)

        # Upgrade socket to RESP3 in one round trip
        hello = send_cmd(sock, f, "HELLO", "3")[1]
        assert isinstance(hello, dict) and hello[b"proto"] == 3
        assert send_cmd(sock, f, "GET", k_miss)[1] is None  # wire is now _\r\n
        assert send_cmd(sock, f, "HGETALL", k_cart)[1] == {b"apples": b"3", b"note": b"gift"}
        assert send_cmd(sock, f, "SMEMBERS", k_tags)[1] == {b"cache", b"ram"}

        # Inspect arity, ACL speed categories, and key extraction
        info = send_cmd(sock, f, "COMMAND", "INFO", "GET", "MGET", "DEL", "LRANGE", "ZADD")[1]
        summary = {row[0].decode(): (row[1], sorted(row[6])) for row in info}
        assert summary["get"][0] == 2 and "@fast" in summary["get"][1]
        assert summary["mget"][0] == -2 and "@fast" in summary["mget"][1]
        assert summary["del"][0] == -2 and "@slow" in summary["del"][1]
        assert summary["lrange"][0] == 4 and "@slow" in summary["lrange"][1]
        assert summary["zadd"][0] == -4 and "@fast" in summary["zadd"][1]

        keys = send_cmd(sock, f, "COMMAND", "GETKEYS", "SORT", "mylist", "ALPHA", "STORE", "outlist")[1]
        assert keys == [b"mylist", b"outlist"]
        print("verified:", summary)
    finally:
        send_cmd(sock, f, "UNLINK", k_bin, k_empty, k_cart, k_tags)
        f.close()

Explain it aloud in an interview

“Clients talk to Redis over TCP using RESP — commands go out as length-prefixed Arrays of Bulk Strings, which gives 512 MB binary safety and trivial framing that naturally supports pipelining. Connections start in RESP2 for compatibility and upgrade via HELLO 3 to get native Maps, Sets, unified Nulls, and out-of-band Push frames. On the server side, every command has published metadata — arity, flags, ACL speed tags, and key specifications — and reading complexity means always checking what N counts: whole keyspace, one container, or caller-supplied arguments.”

Follow-ups to anticipate: why redis-cli --raw differs from TTY output, why MGET is tagged @fast yet still dangerous with huge key lists, and how COMMAND GETKEYS helps Cluster proxies route dynamic-argument commands.

Self-test

1. Why do real Redis clients send *2\r\n$3\r\nGET\r\n$3\r\nfoo\r\n instead of inline GET foo\r\n?

Inline commands split tokens on whitespace and end at \r\n, so spaces, newlines, or \x00 bytes inside a key or value break framing. RESP Arrays of Bulk Strings declare exact byte lengths via $len, making every key and value binary-safe up to 512 MB.

2. On the wire, how do an empty string, a missing key in RESP2, and a missing key in RESP3 differ?

An empty string is $0\r\n\r\n (a 0-byte bulk string). A missing key in RESP2 is $-1\r\n (null bulk string, alongside *-1\r\n for null arrays). After HELLO 3, RESP3 sends unified Null _\r\n.

3. Why did my shell script parse (integer) 2 in my terminal and fail under cron?

redis-cli formats replies for humans only when stdout is a TTY. When redirected or run under cron (non-TTY), it automatically switches to raw output and prints bare 2. Pass --raw or --no-raw explicitly whenever a script parses output.

4. What four things does HELLO 3 AUTH user pass SETNAME api achieve, and why do sockets still open in RESP2?

In one round trip it upgrades the connection to RESP3, authenticates the ACL user, names the connection for CLIENT LIST, and returns a Map of server metadata. Connections still open in RESP2 so older clients and proxies never break unexpectedly.

5. What does an arity of -4 mean in COMMAND INFO ZADD, and why did Redis 7+ add Key Specifications?

Arity counts the command name itself; negative means “at least.” -4 means ZADD plus at least three arguments (key, score, member). Key Specifications (begin_search and find_keys) replaced fixed first/last/step integers so Cluster clients and proxies can locate keys in dynamic commands like ZINTERSTORE, SORT, and EVAL.

6. How do KEYS, HGETALL, MGET, and ZRANGE 0 9 differ even though N appears in all of their complexities?

KEYS scans all keys in the database; HGETALL scans all fields inside one hash; MGET loops over the N keys you passed; ZRANGE 0 9 seeks in O(log N) over the zset and returns only M=10 elements, keeping the call tiny even at millions of members.

7. Which commands belong to @fast vs. @slow, and why can an @fast user still block the event loop?

@fast holds O(1) commands plus bounded O(log N) inserts like ZADD and argument-looping commands like MGET/SADD; @slow holds everything else. Because MGET and SADD loop over client-supplied arguments, passing 100,000 items in a single call passes -@slow yet still blocks the main thread.
